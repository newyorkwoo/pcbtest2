# aipcb — Claude-driven local EDA

Claude is the circuit designer **and** the design reviewer. KiCad 10 (local) is the file format,
ERC/DRC and Gerber engine; `aipcb/` adds the parts KiCad does not automate.
Everything runs offline on this machine.

## Layout
- `aipcb/` engine: `spec.py` (design.yaml model + validation), `library.py` (KiCad libs, custom part generator),
  `schematic.py`, `placement.py` (physics placer), `router.py` (2-layer A* router, rip-up & reroute, GND fan-out),
  `pcb.py`, `zonefix.py` (closed-loop pour repair), `simulate.py` (KiCad's libngspice), `checks.py`, `fab.py`,
  `pipeline.py` (stages + out/status.json), `wiring.py` (physical pin-to-pin wire list), `mcp_server.py`, `gui/app.py`.
- `projects/<name>/design.yaml` — **the single source of truth**. Never hand-edit generated `.kicad_*` files;
  change design.yaml and rebuild.
- `projects/<name>/sim/*.cir` — SPICE decks; `out/` — every generated report/preview/fab file.
- `out/schematic_map.json` + `out/preview/schematic_sheet.svg` (written with the schematic) feed the GUI tab「網路追蹤 Nets」
  (click a wire/pin/part to highlight its connections).
- `out/wiring.json` + `out/wiring_list.csv` (pcb stage): the GUI tab「實體接線圖 Wiring Diagram」— parts at their board
  positions, coloured pin-to-pin wires (MST per net), wire list exportable to CSV / PDF.
- `archive.py` export/import: `project/` (full project, what import uses), `documents/` (requirements / spec /
  description HTML, schematic PDF, BOM, wiring list, review, checks, sims, fab), `manifest.json` (sha256 per file,
  verified on import). Import backs up an existing project to `exports/` before overwriting, rewrites the absolute
  paths in `out/`, and on `--name` renames the KiCad files + design.yaml `project:`. GUI: one project open at a time (no dropdown); closing / switching / quitting asks to save (= snapshot) only if files changed since open / last save (archive.fingerprint).
  Menu 檔案 File: New ⌘N, Open ⌘O, Open Recent, Close Project ⌘W, Save Snapshot ⌘S (export to exports/), Save As ⇧⌘S (duplicate), Import ⇧⌘I, Export ⇧⌘E.
- `projects/<name>/docs/` + `README.md` — committed schematic PDF/SVG and renders, regenerated by `previews`
  (never edit by hand).

## Commands
```
.venv/bin/python -m aipcb build <project>       # full flow (library→…→previews), 1–4 min
.venv/bin/python -m aipcb <stage> <project>     # library validate schematic erc place route pcb drc sim checks previews
.venv/bin/python -m aipcb build <p> --keep      # keep every placed part where it is, place only new ones, re-route
                                               #   (--keep U1,J2 keeps only those; --unlock R5 re-places R5)
.venv/bin/python -m aipcb review-package <p>    # data for the AI review
.venv/bin/python -m aipcb fab <p> [--force]     # gated on checks + review PASS
.venv/bin/python -m aipcb gui [project]         # desktop dashboard (no project: reopens the last one closed)
.venv/bin/python -m aipcb export <p> [--to DIR] [--no-zip]   # archive: one folder + .zip (default ./exports)
.venv/bin/python -m aipcb import <folder|zip|manifest.json> [--name NEW] [--overwrite]
```
MCP server `aipcb` (see .mcp.json) exposes the same flow as tools.
Claude Desktop extension: `.venv/bin/python packaging/mcpb/build.py` → `packaging/mcpb/dist/aipcb.mcpb` (uv runtime,
engine without the GUI; `AIPCB_PROJECTS` / `AIPCB_EXPORTS` set from the install dialog). Desktop never sees this file, so the
designer/reviewer rules it needs live in `aipcb/guide.py` (tool `get_design_guide`) — keep it in step with this file.

## Designing (Claude as designer)
1. Pick parts: `search_symbols`, `get_symbol_pins`, `search_footprints`, `get_footprint_pads`. Prefer KiCad stock
   symbols/footprints. A missing chip goes in `custom_symbols:` (pins `[number, name, type, side]`) with a stock
   footprint where possible — and its pinout must be cross-checked against the datasheet in the review.
2. Nets are `REF.PIN` (pin number, or a pin name — a name shared by several pins selects all, e.g. `U1.GND`).
   Quote tokens containing braces: `"U2.V_{DD}"`. Every pin must be on a net or listed in `nc:`.
3. Placement hints in `place:` — `lock: true` keeps the part where the last placement put it; `edge: top|bottom|left|right` (+`edge_offset`), `x`/`y` (board-relative mm),
   `rot`, `near: REF.PIN` (+`near_dist`) for decoupling / crystals / ESD. Use `block:` to group functions.
4. `rules.power_nets` get `power_track` width; `route_first` for critical nets. Supply rails (GND*, `+…`, and
   rail-like power_nets such as VBUS / AMP_5V; override with `rules.supply_nets`) are drawn as power symbols and
   are named without the `/` prefix on the PCB. The schematic is wired (2-pin parts hang off their IC pin); the
   `schematic` stage fails unless KiCad's netlist of the sheet equals design.yaml pin for pin.
5. Describe the device in `spec:` (`summary`, `blocks:` one plain-language explanation per schematic block, `sections:`
   spec-sheet tables). The GUI shows it beside the schematic as「電路說明」/「規格書」, together with the board,
   key ICs and verification state. Write the product requirements in `requirements:` (purpose, users, scenarios,
   `functional` / `non_functional` items `{id, text, priority: 必要|建議|選配, design, verify}`, constraints,
   out_of_scope, acceptance) — shown as「設計需求書」; a `verify` naming `sim NN` shows that sim's live PASS/FAIL.
   Keep both in step with the design when the circuit changes.
6. Write SPICE decks that **mirror design.yaml exactly** (same topology/values) and state expectations with
   `* @expect`. Derive expected values by hand first; when a sim disagrees, decide whether the design or the
   expectation is wrong and say which.
7. `build_board` → read `checks`, `erc`, `drc`; fix design.yaml (or placement hints) and rebuild until DRC has
   0 errors / 0 unconnected.

## Reviewing (Claude as reviewer) — before any fab export
Call `get_review_package`, go through every item of `review_checklist`, verify each IC pin against its datasheet
knowledge, then `submit_review` with PASS / CONDITIONAL / FAIL and concrete findings. Only PASS unlocks
`export_fab` (`force` is for prototypes and is recorded in the manifest). Be honest: unverifiable items
(e.g. AI-generated pinouts, LCSC numbers) are CONDITIONAL, not PASS.
